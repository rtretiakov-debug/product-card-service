# Product Card Service

Локальное приложение для подготовки черновиков карточек контрольно-измерительных приборов для B2B-интернет-магазина. Перед публикацией менеджер должен проверить результат самостоятельно.

## Требования

- Python 3.11 или новее.
- [uv](https://docs.astral.sh/uv/) для установки зависимостей из `uv.lock`.
- API-ключ и доступ к выбранной LLM-модели через OpenAI API или совместимый API endpoint.

## Установка

Установите `uv`, если он ещё не установлен:

```powershell
py -3.11 -m pip install uv
```

На macOS или Linux используйте `python3.11 -m pip install uv`.

Из корневой папки проекта установите зависимости приложения и тестов:

```powershell
uv sync --extra test
```

Команда создаёт виртуальное окружение `.venv` и устанавливает зафиксированные в `uv.lock` зависимости.

## Настройка провайдера

Создайте файл `.env` в корневой папке проекта и укажите параметры выбранного OpenAI API или совместимого endpoint:

```dotenv
OPENAI_API_KEY=your-api-key
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=your-model-name
```

Замените `your-api-key` и `your-model-name` на значения, выданные вашим провайдером; при необходимости укажите его API endpoint в `OPENAI_BASE_URL`. Это пример с заполнителями, а не рабочие учётные данные. Не публикуйте и не коммитьте настоящий ключ: `.env` исключён из Git.

Все три параметра обязательны. Приложение сообщает об отсутствующих или некорректных настройках при запуске.

## Запуск

Из корневой папки проекта запустите приложение:

```powershell
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
```

После запуска:

- Откройте веб-форму: <http://127.0.0.1:8000/>.
- Проверьте доступность приложения: <http://127.0.0.1:8000/health>.
- Интерактивная документация HTTP API доступна по адресу <http://127.0.0.1:8000/docs>.

Сервер привязан к loopback-адресу `127.0.0.1` и предназначен для локального использования.

## Использование API

Отправьте `POST /products/generate` с JSON-объектом. Поля `name`, `manufacturer` и `description` обязательны; `specs` — необязательный объект строковых характеристик:

```json
{
  "name": "Манометр DM 02",
  "manufacturer": "Манотомь",
  "description": "Описание или вставленный текст из паспорта прибора.",
  "specs": {
    "диапазон измерений": "0–1,6 МПа",
    "класс точности": "1,5"
  }
}
```

По умолчанию API возвращает JSON. Чтобы получить Markdown, добавьте `?format=markdown` к адресу запроса. Для JSON тип ответа — `application/json`, для Markdown — `text/markdown`.

Результат включает поля `seo_title`, `seo_description`, `search_queries`, `commercial_block`, `name`, `manufacturer`, `specs` и `description`. Исходные название и описание сохраняются (описание — без изменений); пустой производитель и отсутствующие характеристики обозначаются маркером `«данных нет»`. Переданные характеристики сохраняются. SEO-заголовок ограничен 70 символами, SEO-описание — 800–1200 символами, число поисковых запросов — от 3 до 5. Если входные данные или ответ провайдера не позволяют сформировать корректную карточку, приложение возвращает ошибку, а не неполный успешный результат.

Веб-форма на `/` принимает те же данные и позволяет выбрать JSON или Markdown. Характеристики в форме вводятся как JSON-объект.

Ошибки проверки входных данных возвращаются с HTTP-статусом `422`; ошибки провайдера или несоответствие результата требованиям — со статусом `502`.

## Тесты

После установки зависимостей запустите тесты:

```powershell
uv run pytest
```

### Сквозной тест с реальным LLM-провайдером

Отдельный сквозной тест запускает приложение с настройками из `.env` и отправляет
реальный запрос настроенному провайдеру. Запускайте его отдельно: запрос может
потреблять квоту или тарифицироваться провайдером.

```powershell
uv run pytest tests_e2e/test_product_generation.py -v
```

## Ограничения и данные

- Это локальный прототип: приложение не предоставляет учётные записи, доступ по локальной сети или совместную работу.
- Поддерживается один настроенный OpenAI API или совместимый endpoint; ключ, адрес и модель задаются через `.env`.
- Вводится текст описания или паспорта. Загрузка и распознавание PDF и других файлов не поддерживаются.
- Приложение не сохраняет запросы или результаты, не ведёт историю и не использует базу данных.
- Введённые данные отправляются выбранному LLM-провайдеру для генерации. Приложение не контролирует и не обещает политику хранения данных провайдером.
- Результат является черновиком: перед использованием проверьте его фактическую точность и соответствие исходным данным.
